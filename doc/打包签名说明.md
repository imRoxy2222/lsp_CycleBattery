# 打包签名说明

## 密钥信息

| 项目 | 值 |
| --- | --- |
| 密钥库文件 | `keystore/cyclebattery.jks` |
| 别名（alias） | `cyclebattery` |
| 算法 | RSA 4096（SHA384withRSA） |
| 有效期 | 100 年（36500 天） |
| 密码 | 见 `keystore.properties`（store 与 key 密码相同） |
| 证书主体 | CN=ColorOS17CycleBattery, OU=Personal, O=imroxy2222, C=CN |

> 本项目为私有仓库，密钥与 `keystore.properties` 均随仓库提交，**未**加入 `.gitignore`。

## Gradle 接入方式

- `app/build.gradle.kts` 读取根目录 `keystore.properties`：
  ```properties
  storeFile=keystore/cyclebattery.jks
  storePassword=...
  keyAlias=cyclebattery
  keyPassword=...
  ```
- `signingConfigs` 创建名为 `module` 的配置，同时应用于 **debug** 与 **release** 构建
  （两个构建类型同签名，可直接互相覆盖安装，无需先卸载）
- 若 `keystore.properties` 不存在（如 CI 拉取后未附带密钥），构建仍可进行：
  release 回退为未签名，debug 回退为默认 debug 签名

## 版本号规则

| 项 | 规则 |
| --- | --- |
| `versionName` | 固定 `1.0` |
| `versionCode` | **当前分支提交 commit 数**（`git rev-list --count HEAD`），构建时自动读取 |

- 实现位于 `app/build.gradle.kts`：`CommitCountValueSource`（Gradle `ValueSource`），
  与配置缓存兼容——commit 数变化时 Gradle 自动失效缓存并重新取值
- 每次提交后重新打包，versionCode 自动 +1，可直接覆盖安装升级
- git 不可用（未初始化仓库/无 git 命令的环境）时回退为 `1`，保证构建永不因版本号失败
- `minSdk = 35`（Android 15）；代码本身无厂商私有依赖，降 minSdk 仅放宽安装门槛

## 常用命令

```bash
# 构建（产物：app/build/outputs/apk/release/app-release.apk，已签名）
gradlew assembleRelease

# 查看证书信息
keytool -list -v -keystore keystore/cyclebattery.jks -alias cyclebattery

# 校验 APK 签名
apksigner verify --print-certs app/build/outputs/apk/release/app-release.apk
```

## 自动发布（GitHub Actions）

工作流：`.github/workflows/release.yml`——**推送 tag 自动构建 Release 并发布**。

### tag 规则

格式为 **`N-C`**（如 `1-9`）：

| 字段 | 含义 |
| --- | --- |
| `N` | 版本序号，从 **1** 开始；**必须已存在 N-1 号 tag 才允许打 N**（严格连续，不允许跳号、重号） |
| `C` | tag 所指提交在 master 上的 commit 数（即 APK 的 versionCode） |

首次发布示例（当前仓库 9 个 commit）：`git tag 1-9 && git push origin 1-9`。

### workflow 的四重校验（任一不符即失败，不产生 Release）

1. tag 格式必须为 `N-C`
2. 序号 N 必须等于已有版本 tag 数 + 1（隐含 N-1 已存在、不跳号）
3. tag 所指提交必须在 master 分支上
4. 实际 commit 数必须等于 C；构建后还会用 aapt2 复核 APK 的 versionCode 与 C 一致

### 构建环境

- JDK 21（Temurin）+ Gradle wrapper；`fetch-depth: 0` 完整检出（versionCode 依赖 commit 历史）
- 签名密钥优先从仓库 **Secrets** 还原（`KEYSTORE_BASE64` / `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`，
  其中 jks 需 base64 编码）；未配置 Secrets 时回退使用仓库内已提交的密钥文件
- Release 由 `softprops/action-gh-release@v2` 创建，附件为 `app-release.apk`，标题 `环形电量 v<tag>`

### 同步发布到 LSPosed 模块仓库

源仓库 Release 发布成功后，workflow 会自动把 APK 发布到
[Xposed-Modules-Repo/io.github.imroxy2222.lsp_coloros17cyclebattery](https://github.com/Xposed-Modules-Repo/io.github.imroxy2222.lsp_coloros17cyclebattery)，
LSPosed 官方 bot 会自动索引。

**bot 的索引规则**（官方要求）：

| 要求 | 处理方式 |
| --- | --- |
| 仓库描述（About）非空且为模块名 | workflow 自动 PATCH 为 `环形电量` |
| Release 附件含 `.apk`，tag 为 `VersionCode-VersionName` | workflow 自动以 `9-1.0` 这样的 tag 建 Release 并上传 APK |
| 仓库有 README | 从 `module-repo/README.md` 自动同步 |

**一次性配置（需要你手动做）**：

1. 创建 Fine-grained Personal Access Token（GitHub → Settings → Developer settings →
   Fine-grained tokens）：
   - Repository access → Only select repositories → 选 `Xposed-Modules-Repo/io.github.imroxy2222.lsp_coloros17cyclebattery`
   - Permissions → Repository permissions → **Contents: Read and write**
2. 在自己的仓库 `imRoxy2222/lsp_CycleBattery` → Settings → Secrets and variables → Actions →
   New repository secret：名称 `MODULE_REPO_TOKEN`，值为该 Token

未配置 `MODULE_REPO_TOKEN` 时，workflow 会在主 Release 发布成功后跳过 LSPosed 同步并给出警告，不会失败。

**注意**：

- LSPosed 仓库的 Release tag 是 `VersionCode-VersionName`（如 `9-1.0`），与源仓库的 `N-C` tag 是两套编号，
  同一 versionCode 重复发布会报错退出
- 模块仓库的 README 每次发布都会被 `module-repo/README.md` 覆盖同步，改介绍请改这个文件

### 注意

- **不要删除旧 tag**：序号校验基于现存 tag 计数，删了中间的 tag 后，下一次推送会被判定为序号不连续
- versionCode = commit 数，因此 **tag 必须在最后一次 push commit 之后打**，否则校验 4 会失败
- 换 master 之外的分支打 tag 会被校验 3 拒绝

## 换机/重建密钥

签名一旦发布就不要更换，否则用户必须卸载重装（Xposed 模块配置会丢失）。
请妥善备份 `keystore/` 目录与 `keystore.properties`。
